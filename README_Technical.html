💻⚛️ Hybrid Classical-Quantum Environment

Applies to modules linking to background QPU providers (e.g., QFLCH).

If running the dashboard in Hybrid Mode to dispatch jobs to real Quantum Processing Units (QPUs):

  • 🤝🔑 API Access: A valid API Token from the provider (e.g., IBM Quantum, IonQ, or Rigetti) is required to authenticate job submission.
  • ⚙️⏳ Job Latency: Real-time visualization may pause while jobs are queued in the provider's cloud execution stack.
  • 🛡️🔄 Fallback Protocol: If the QPU endpoint is unreachable or the user lacks credentials, the system defaults to the Local Classical Simulator.

⚠️ Performance Constraints & Warnings

Note: The simulation engine is optimized for stability, but local hardware limits apply.

  • ⚛️👥🛑 Particle Population Limit: High ambient/background swarm counts (N > 400) may trigger CPU utilization spikes (>90%) due to the linear cost of particle-interaction calculations whilst maintaining e.g., a tripartite quantum communication network (entanglement).
  • ⚛️🚧 Particle Threshold: High density clusters will reduce frame rates.
  • 🖼️⏳ Rendering Lag: If the browser frame rate drops below 30 FPS, the following safety warning will appear:

    ⚠️ Warning: High ambient swarm counts ($N > 400$) may cause cascade simulation lag due to local hardware rendering limits.
    ⚠️ Warning: High ambient swarm capture between hypercube entangled nodes (Spatial Density near 2, AND, Nu Adjustment Factor ($\nu$ near 0.9)) may cause cascade simulation lag due to local hardware rendering limits.

  • 🔥📉 Thermal Throttling: Extended runtime of "QDF-Lens" or high-density hypercubes on laptops may cause fan spin-up. Ensure adequate ventilation.
  • 🧵⚙️ Job Threads: Background Python threads manage the QPU queue to prevent browser freezing.

🖥️🛠️▶ Environmental Setup & Execution

Method 1: Direct Offline Launch
To run QF-LC widget assets offline, download the HTML widget(s) of your choice along with their dependent files. Simply double-click the file to run it in your browser (e.g., Edge, Chrome).

Method 2: Local Python Server (Recommended)
To run Python-based widgets locally with full module support, follow these steps to ensure your environment meets the Project Setup & System Requirements.

Step A: Verify Python Installation
Since these widgets rely on Python logic, ensure Python is installed. If not, download it from python.org/downloads.

Step B: Start the Local Server
Open your terminal (Command Prompt, PowerShell, or Terminal). Change directories to the folder containing your downloaded widget:

cd path/to/your/folder

Run the built-in HTTP server command:

python -m http.server 8000

⚠️ Note: If python doesn't work, try python3 -m http.server 8000

Step C: Launch in Browser
Open your web browser and navigate to: http://localhost:8000

⚠️💥🛠️ Troubleshooting & Updates
If you encounter errors, press F12 to open Developer Tools and check the console. Ensure your HTML file headers use the active PyScript release below to avoid version conflicts:

<head>
... <!-- HTML program code -->
<!-- Official Latest PyScript CDN Assets; Core PyScript External Dependencies -->
<link rel="stylesheet" href="https://pyscript.net/releases/2026.3.1/core.css" />
<script type="module" src="https://pyscript.net/releases/2026.3.1/core.js"></script>
</head>

📦⚙️ Library Installation (Local Dependencies)
To avoid import errors, upgrade pip and install the required scientific libraries:

pip install --upgrade pip
pip install numpy scipy matplotlib qiskit pandas scikit-learn
